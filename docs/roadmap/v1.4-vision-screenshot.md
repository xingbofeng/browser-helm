# v1.4 — Vision/Screenshot Agent

## 1. 背景

A11y 和 DOM 不能覆盖 canvas、图表、地图、遮挡、视觉布局错位等问题。用户会需要 agent 看见页面视觉状态，但 BrowserHelm 仍然坚持 DOM/a11y-first，vision 是增强能力而不是基础路径。

当前用户遇到的问题：按钮被遮挡、布局错位、canvas/chart/map 内容无法通过 DOM 理解。

现有系统限制：没有截图工具、vision model input、overlay/layout detector、坐标 fallback。

为什么现在要做：补足结构化观察无法处理的视觉世界。

## 2. 用户故事

US1. 作为用户，我希望 agent 能识别页面遮挡或布局问题，以便理解为什么按钮不可点或页面看起来异常。

US2. 当截图不可用或模型不支持视觉时，作为用户，我希望系统回退到 DOM/a11y 解释，以便任务不中断。

US3. 作为前端开发者，我希望 agent 能对比视觉状态和 DOM 状态，以便发现可见但不可交互、DOM 存在但视觉隐藏的问题。

US4. 作为用户，我希望坐标点击只作为最后手段，以便减少误点风险。

## 5. 产品方案

### 功能入口

DebugPanel / ObservationPanel 中增加“视觉检查”入口；agent 在 DOM/a11y 不足时可调用 vision tools。

### 用户路径

用户描述视觉问题 -> agent capture viewport -> vision model 描述状态 -> agent 结合 DOM/a11y 判断原因 -> 给出解释或使用 pointer fallback。

### 正常状态

展示截图缩略图、视觉摘要、发现的遮挡/布局问题。

### 空状态

当前模型不支持 vision 时展示“当前 provider 不支持视觉输入”。

### 错误状态

截图失败、权限不足、页面不可截图、vision model error 都要回退 DOM/a11y。

### 权限 / 可见性

截图可能包含敏感信息，必须在 trace 中可控保存；默认只保存必要摘要。

## 7. 技术方案

### 现状

无 screenshot/vision 工具。

### 目标设计

Vision tools 在 background 截图，模型层支持 multimodal input；结果以视觉摘要回到 agent loop。

### 数据流 / 调用链

Agent -> bh_vision_capture_viewport -> screenshot-manager -> vision-client -> vision summary -> ToolResult -> AgentLoop。

### 关键类型 / API

```ts
type VisionObservation = {
  imageRef?: string;
  summary: string;
  visibleText?: string[];
  blockers?: string[];
  layoutIssues?: string[];
};
```

### 错误处理

Vision failure 不能阻断 DOM/a11y path。坐标点击必须经过 risk policy。

### 复用与约束

优先复用：ModelClient capability flags、ToolResult、TraceEvent。

不要重复实现：page observe、element click 主路径。

## 10. 验收标准

AC1. 覆盖 US1：当页面存在 overlay 或明显视觉布局异常时，系统会通过 vision 工具生成可行动解释。

AC2. 覆盖 US2：当 vision 不可用时，系统回退 DOM/a11y，并显示明确原因。

AC4. 覆盖 US4：坐标点击不会作为首选工具，并且敏感场景需要 approval。

AC5. 已有 DOM/a11y-first 行为不受影响。
