# v0.31 — Interactive Elements Prototype

## 1. 背景

v0.3 定义了结构化页面数据总层，v0.31 负责把 ref map 进一步派生成可读、可筛选、可检查的交互元素数据。

当前用户遇到的问题：页面里哪些元素可点、可输入、可选择还不清楚，Agent 和 UI 都只能看到较粗的 observation。

现有系统限制：缺少统一 interactive element schema，无法稳定表达 role、name、state、visible、disabled、checked、selected。

为什么现在要做：交互元素是后续表单字段、安全动作、Cockpit 交互元素 tab 的基础。

## 2. 用户故事

US1. 作为用户，我希望看到页面上有哪些可交互元素，以便理解 Agent 可能操作什么。

US2. 作为开发者，我希望每个交互元素都带有 ref_id、role、name 和状态，以便后续工具不用猜 selector。

US3. 当元素不可见或 disabled 时，作为 Agent，我希望状态能明确表达，以便避免错误动作。

US4. 作为 UI 开发者，我希望交互元素可搜索、可筛选、可选中查看详情。

## 3. 目标

本 Issue 要完成：

- 实现 interactive element discovery。
- 定义 InteractiveElement schema。
- 支持 role/name/state/visible/disabled/checked/selected。
- 提供交互元素 tab data。
- 支持 empty state 和 REF_STALE 错误。

### 任务拆解

- T1. 实现 interactive-filter。
- T2. 实现 element state reader。
- T3. 实现 accessible name / role normalization。
- T4. 实现 `bh_a11y_find_interactive`。
- T5. 实现 `bh_element_inspect`、`bh_element_read_state`。
- T6. 补充交互元素 fixtures 和测试。

## 4. 不做什么

本 Issue 明确不处理：

- 不做完整 UI。
- 不做表单字段诊断。
- 不做 click/type 等 mutating action。
- 不做 iframe/shadow DOM 深度支持。

## 5. 产品方案

### 功能入口

通过 v0.3 structured page data 构建交互元素列表。

### 用户路径

observe 页面 -> ref map -> 交互元素扫描 -> 输出交互元素 tab data。

### 正常状态

返回按可见性和重要性排序的交互元素列表。

### 空状态

没有交互元素时返回 empty reason。

### 错误状态

ref stale、元素状态不可读、role/name 解析失败都返回结构化错误。

### 权限 / 可见性

只读，不执行动作。

## 7. 技术方案

### 现状

已有 ref map，但交互元素只是 observation 中的粗略候选。

### 目标设计

基于 ref map 和 DOM/a11y 信息构建 interactive element list。

### 数据流 / 调用链

ref map -> interactive-filter -> element state reader -> InteractiveElement[] -> tab data。

### 关键类型 / API

```ts
type InteractiveElement = {
  refId: string;
  role?: string;
  name?: string;
  tagName: string;
  visible: boolean;
  disabled: boolean;
  checked?: boolean;
  selected?: boolean;
};
```

### 错误处理

单个元素解析失败不阻断整个列表，失败项进入 warnings。

### 复用与约束

优先复用：v0.2 ref map、accessible-name、role-resolver。

不要重复实现：selector 猜测、动作执行器、UI store。
