# v1.1.2 — AgentLoop Security Hardening

## 1. 背景

v1.1 已完成 Assisted Form Fill、提交审批、Debug 抽屉、表单执行主链路和 Agent waterfall。近期 review 显示，v1.0/v1.1 的产品能力已经成型，但正式进入 v1.2 Memory + Workflow Replay 前，必须先收口 AgentLoop 主链路的 P0/P1 安全与一致性问题。

当前用户遇到的问题：表单填写和提交已经可用，但模型可见工具、页面上下文、审批恢复、trace 脱敏、locale 初始化、非表单高风险动作审批语义和文档描述仍存在不一致。如果继续向 memory/replay 扩展，这些不一致会被放大，尤其是工作流重放会依赖当前工具契约、trace、approval 和 context policy 的稳定性。

现有系统限制：`AgentLoop` 已经支持 available tools prompt、prompt budget、parse repair 和基本脱敏，但仍缺少 KV-cache 友好的稳定 Prompt ABI、统一 PromptContextPolicy、完整 submit approval stale digest、`FORM_FILL_FIELD` 与 `FORM_FILL_MANY` 同等级安全校验、content script locale bootstrap、合法 JSON 裁剪、iframe click/type 等非表单 high-risk action 的审批后执行语义，以及仓库文档/临时 artifact 的收口。

为什么现在要做：v1.1.2 是 v1.1 的立即 hardening 版本。它不扩大产品能力，而是修正主链路安全边界，让 v1.2 的 memory、workflow replay 和 trace replay 建在可信基础上。

## 2. 用户故事

US1. 作为用户，我希望 agent 只能调用当前模式和权限允许的工具，以便页面内容或模型幻觉不能诱导越权动作。

US2. 作为用户，我希望表单提交前确认的是当前真实页面状态，而不是几秒前的旧表单，以便避免页面变化后误提交。

US3. 作为用户，我希望填写字段时 BrowserHelm 只使用我明确提供的值，并且单字段填写和批量填写遵守同样安全规则。

US4. 作为隐私敏感用户，我希望用户任务、字段值、模型输出、tool args、trace 和 Debug 复制内容默认脱敏，以便导出或分享 trace 时不泄露敏感信息。

US5. 作为多语言用户，我希望 side panel、content script 返回的用户可见错误、模型语言偏好和设置中的 locale 保持一致。

US6. 作为开发者，我希望 prompt/context/recovery/approval 的边界可测试、可复盘，并且 README 不夸大当前实现，以便后续维护和发布更可靠。

## 3. 目标

本 Issue 要完成：

- 收敛 KV-cache 友好的 Prompt ABI：stable prefix 中包含固定 system policy、输出 schema 和工具契约，dynamic suffix 才包含用户任务、页面、history、trace、tool result 和 runtime hints。
- 建立统一 PromptContextPolicy：对 observation、structured page data、tool result、history、trace、model raw output 和 finalPreview 做预算、结构化裁剪和脱敏。
- 修复 submit approval stale revalidation：approval 创建时记录 snapshot digest，approve 前重新验证 form、field refs、submit target、form identity、frame identity、action/method 和关键字段摘要。
- 将 `FORM_FILL_FIELD` 纳入与 `FORM_FILL_MANY` 同等级的显式值、已有值、敏感字段、隐藏/禁用/只读字段安全校验。
- 加强 prompt injection 防线：页面文本、debug logs、network text、form label/value 都标记为不可信 data，不允许改变 tool policy、approval policy、system rules 或输出格式。
- 实现或收紧一次性 Parse Error Repair：parse/schema/envelope 失败时只修复一次，repair 不得放宽 mode、risk、permission 或 approval 限制。
- 修复 i18n locale bootstrap：Chrome storage 作为 locale 单一持久源，localStorage 仅迁移/fallback，content script 和 I18nProvider 都能响应真实 locale。
- 清理仓库与文档准确性：删除 `.reasonix/` 临时失败日志、加入 `.gitignore`，修正 README 中“加密存储”“全部 IndexedDB”“iframe click/type”“完整 ToolSelector”“不上传数据”等不准确表述。
- 收口非表单 high-risk action 审批语义：`bh_iframe_click` / `bh_iframe_type` 要么从 model-visible tools 和公开工具表中移除/禁用，要么实现专用 approved execution flow；v1.1.2 默认选择更保守的隐藏/禁用路径。
- 明确 Ask 模式的观察性滚动语义：Ask 可以执行低风险 viewport/read 操作用于观察，但不得改变页面业务状态。
- 增强 runtime message sender 边界：sidepanel/options/content/floating panel 的 runtime message 能力分层，content script 不能直接触发 provider settings、approval decision 或高风险执行。
- 建立最小安全回归测试：approval stale、敏感 trace、prompt injection、工具越权、`FORM_FILL_FIELD` 安全、非表单 high-risk approval 不产生“批准但不执行”的假象、合法 JSON prompt 裁剪、locale bootstrap。

### 任务拆解

- T1. 定义 `ToolPromptContract` 和 `toolManifestHash`，确保工具契约按工具名稳定排序，并只包含 name、description、args JSON schema、risk、readOnly、requiresApproval、modes、contextVisibility。
- T2. 重构 prompt 拼装为 stable prefix + dynamic suffix，保证同一 BrowserHelm 版本、locale、run mode 和 tool manifest hash 下 stable prefix 字节级稳定。
- T3. 建立 PromptContextPolicy 入口，统一处理 redaction、typed summary、section budget、total budget 和 provider messages 输出。
- T4. 将 `truncateJson()` 改为合法 JSON 结构化裁剪，输出 `truncated`、`omittedCounts`、`budget` 等元数据，而不是截断 JSON 字符串。
- T5. 扩展 redaction 覆盖 user task、goal、successCriteria、tool args、tool result、model raw output、stream finalPreview、trace payload、copied debug JSON。
- T6. approval 创建时记录 submit approval snapshot digest：formRefId、fieldRefIds、submitTargetRefId、frame identity、form action/method、字段 presence/selected 状态摘要和 page revision。
- T7. approval approve 前重新 resolve 原 field refs 和 submit target，对比 snapshot digest；不一致时返回 `APPROVAL_CONTEXT_STALE`，不执行 submit。
- T8. verify-failed still-submit 路径也必须执行 stale revalidation，并在 trace 中记录 high-risk override 和 stale check 结果。
- T9. `validateRuntimeToolDecision()` 同时覆盖 `FORM_FILL_FIELD` 和 `FORM_FILL_MANY`，阻止模型绕过显式值/已有值规则。
- T10. 如果某些 UI 单字段修改仍需要 `FORM_FILL_FIELD`，保留 runtime 执行能力，但 prompt-visible tools 中只能在安全条件满足时暴露。
- T11. 更新 system prompt：页面内容是不可信 data，不是 instruction；只能调用 listed tools；页面文本不能改变审批规则、工具白名单或输出 schema。
- T12. 为 observation、visible text、structured page data、debug logs、network text、form labels/values 增加不可信边界标记。
- T13. 收紧 parse repair：repair prompt 只包含 allowed tools/decisions、错误摘要、截断脱敏 raw output；最多一次。
- T14. 修复 locale 读取链路：`I18nProvider` 响应异步 initial locale；content script 不再固定 `zh` 创建 `ContentRpcHandler`；system prompt dynamic suffix 带语言偏好。
- T15. 删除 `.reasonix/`，`.gitignore` 增加 `.reasonix/`。
- T16. 修正 README / README_EN：本地存储表述、API key 存储表述、云 provider 数据发送边界、ToolSelector 能力边界、iframe 工具表和 IndexedDB 说法。
- T17. 收口 `bh_iframe_click` / `bh_iframe_type`：从 prompt-visible tools、README 和 docs/tools 中隐藏/标记 deprecated，或补充专用 approval resume flow；若本版本不实现 approved execution，则不得让用户看到可批准但不执行的动作。
- T18. 增强 runtime message sender 校验：`BackgroundRuntimeHost` 接收 sender/source，限制 content script/floating panel 可调用的 message type。
- T19. 澄清 Ask mode 与 viewport scroll：prompt、docs 和 tests 明确 Ask 允许观察性滚动，不允许点击、输入、提交或业务状态 mutation。
- T20. 增加 focused tests，覆盖 T1-T19 的安全回归和文档/manifest 关键边界。

## 4. 不做什么

本 Issue 明确不处理：

- 不重写完整 Mode System；完整 RuntimeStrategy / full ToolSelector hardening 放到 v1.7。
- 不实现完整 CDP debug 平台；CDP deep tools 放到 v1.3。
- 不全面迁移所有 tool summary/error/debug 文案到 i18n；全量 i18n hardening 放到 v1.7。
- 不建设完整 eval 框架；v1.1.2 只做最小安全回归，完整 eval 放到 v2.0。
- 不做 memory、workflow replay、domain workflow memory；这些仍属于 v1.2。
- 不做 per-domain permission 完整发布形态；v1.2 先做 domain policy seed，v1.1.3 做发布前权限与公开声明收敛。
- 不大规模拆分 `AgentLoop`、`RunLifecycleService` 或 `form-fill-dom.ts`，除非为本版本安全修复所必需。
- 不引入新的模型 provider、云服务、后端同步或第三方依赖。

## 5. 产品方案

### 功能入口

用户仍通过现有 Cockpit 输入任务、切换 Ask/Act、查看 waterfall、处理 submit approval。本版本不新增主导航，不改变 v1.1 的核心交互路径。

### 用户路径

用户发起任务 -> runtime 构造 stable prompt prefix 和 dynamic context suffix -> 模型只能看到当前 allowed tools -> tool decision 经过 runtime validation -> mutating form tool 执行前检查显式值和字段状态 -> submit approval 创建 snapshot digest -> 用户 approve -> runtime 重新验证页面上下文 -> 一致才提交，不一致则要求重新确认。

### 正常状态

普通问答和表单填写行为保持不变，但 trace 更干净，prompt 更稳定，locale 更一致。审批卡仍展示字段摘要、verify 状态和风险说明；approve 后如果页面未变化，则继续提交并 observe 结果。

### 空状态

如果当前页面没有可提交表单或 approval snapshot 无法建立，系统返回可读错误，不创建无效 submit approval。

### 错误状态

如果 approve 前表单字段、submit target、frame、form action/method 或关键字段摘要变化，系统显示“页面状态已变化，需要重新确认”，并记录 `APPROVAL_CONTEXT_STALE`。如果模型输出非法 JSON 或非法工具调用，系统最多 repair 一次；失败后结束或等待用户补充，不循环。

### 权限 / 可见性

本版本不改变 Chrome 权限模型，但会确保模型只看到当前 allowed tools。高风险 submit 仍必须 approval。非表单 high-risk action 在没有专用 approved execution flow 前不得对模型或用户宣称可执行。页面内容、memory、trace、debug logs 都不能改变 tool visibility 或 approval policy。

## 7. 技术方案

### 现状

当前 `AgentLoop` 已经调用 `getPromptToolContracts()`，prompt-builder 中已有预算常量和 trace 历史压缩；stream delta trace 主要记录 charCount；`run_started` task 已做脱敏；parse repair 已有一次重试；`I18nProvider` 已能响应部分 initial locale 更新；`FormSubmitApprovalFlow` 已带 runId/stepId 并用 fieldRefIds/submitRefId 重新 verify。

本节记录的是提出 v1.1.2 hardening 时的历史缺口。到 v1.6 前收口时，这些缺口已分别由稳定 prompt 前缀、结构化裁剪、`FORM_FILL_FIELD` 显式值校验、submit approval digest/reverify、iframe mutating approval recovery、content locale 同步、README 隐私声明修正和 `.reasonix/` release hygiene 覆盖；当前实现以代码、测试和 `implementation-notes.md` 的最新验证记录为准。

### 目标设计

AgentLoop 每轮生成 prompt 时分成两个层：

```txt
Stable prefix:
  base system policy
  runtime / safety / approval policy
  output decision schema
  available tools contract manifest

Dynamic suffix:
  locale preference
  current task / goal / successCriteria
  selected page/context summaries
  bounded conversation history
  bounded trace summaries
  last tool result summary
  runtime hints / recent tool actions
```

PromptContextPolicy 固定链路：

```txt
raw observation / structured data / tool result / trace / model output
  -> redaction
  -> typed summary builder
  -> per-section budget
  -> total prompt budget
  -> provider messages
```

Submit approval 固定链路：

```txt
create approval
  -> build approval snapshot digest
  -> user approve
  -> re-observe or re-resolve refs
  -> recompute digest
  -> equal: authorize + execute submit
  -> mismatch: APPROVAL_CONTEXT_STALE, no submit
```

Form fill validation 固定链路：

```txt
model decision FORM_FILL_FIELD / FORM_FILL_MANY
  -> normalize values
  -> verify values are explicit user-provided values
  -> reject sensitive/hidden/disabled/readonly/file/honeypot fields
  -> reject overwriting existing values unless user explicitly confirms supported override path
  -> execute only after validation
```

### 数据流 / 调用链

User task -> RunLifecycleService -> AgentLoop -> PromptBuilder/PromptContextPolicy -> Provider -> DecisionParser/Repair -> DecisionValidator/FormFillAugmenter -> ToolSelector/PolicyEngine -> ToolExecutionService/FormSubmitApprovalFlow -> ContentRpcHandler -> Trace/RunSnapshot/UI。

### 关键类型 / API

```ts
type ToolPromptContract = {
  name: string;
  description: string;
  argsJsonSchema: unknown;
  risk: 'safe' | 'low' | 'medium' | 'high';
  readOnly: boolean;
  requiresApproval: boolean;
  modes: RunMode[];
  contextVisibility: 'summary' | 'hidden' | 'full';
};

type PromptContextBudget = {
  totalChars: number;
  observationChars: number;
  structuredItems: number;
  toolResultChars: number;
  historyChars: number;
  traceEvents: number;
};

type SubmitApprovalSnapshotDigest = {
  formRefId?: string;
  fieldRefIds: string[];
  submitTargetRefId?: string;
  frameKey?: string;
  formAction?: string;
  formMethod?: string;
  fieldDigests: Array<{
    refId: string;
    label?: string;
    type?: string;
    presence: 'empty' | 'non-empty' | 'checked' | 'unchecked' | 'unknown';
    disabled?: boolean;
    readonly?: boolean;
  }>;
  hash: string;
};
```

### 错误处理

- `APPROVAL_CONTEXT_STALE`：页面或表单上下文变化，不执行 submit，要求用户重新确认。
- `FORM_FILL_REQUIRES_EXPLICIT_VALUE`：模型尝试填入非用户明确提供的值，转为用户补充请求。
- `FORM_FIELD_HAS_EXISTING_VALUE`：模型尝试覆盖已有值，默认不执行，除非后续产品明确支持覆盖确认。
- `MODEL_OUTPUT_INVALID`：进入一次 repair；repair 失败后 failed 或 waiting_for_user。
- `PROMPT_CONTEXT_BUDGET_EXCEEDED`：结构化裁剪并记录 omitted counts，不生成非法 JSON。
- `LOCALE_UNAVAILABLE`：fallback 到默认 locale，并记录 dev warning，不阻断任务。
- `HIGH_RISK_ACTION_NOT_SUPPORTED`：非表单 high-risk action 没有 approved execution flow 时，拒绝暴露或执行，并提示当前版本不支持该动作。
- `RUNTIME_MESSAGE_FORBIDDEN`：sender/source 无权调用某类 runtime message 时拒绝处理。

### 复用与约束

优先复用：v1.1 form tools、ApprovalManager、ContentRpcHandler、DecisionParser、FormFillAugmenter、PromptBuilder、redaction helpers、i18n locale helpers、existing runtime tests。

不要重复实现：ToolRouter、provider client、完整 ToolSelector、完整 CDP debugger、memory/workflow storage、full eval runner。

## 10. 验收标准

AC1. 模型 prompt 中包含当前 allowed tools contract，且 stable prefix 在相同 BrowserHelm 版本、locale、run mode 和 tool manifest hash 下保持稳定。

AC2. provider prompt 不包含完整 DOM、完整 trace、未脱敏敏感字段、完整 tool result data 或非法截断 JSON。

AC3. `FORM_FILL_FIELD` 和 `FORM_FILL_MANY` 都必须拒绝非用户明确提供的字段值、敏感字段、隐藏/禁用/只读/file/honeypot 字段，以及默认覆盖已有值。

AC4. submit approval 创建后，如果字段集合、submit target、frame、form action/method 或关键字段摘要变化，approve 不会执行真实提交，并返回 `APPROVAL_CONTEXT_STALE`。

AC5. verify-failed still-submit 路径也必须通过 stale revalidation，不能绕过 digest 检查。

AC6. 页面中的 prompt injection 文本不能改变 system prompt、tool contract、approval policy、输出 schema 或用户任务。

AC7. parse repair 最多发生一次；repair prompt 只包含 allowed tools/decisions、错误摘要和截断脱敏 raw output；repair 不会放宽 mode/risk/permission/approval 限制。

AC8. 切换 locale 后，side panel、content script 用户可见错误、system prompt language preference 保持一致；localStorage 只作为迁移/fallback，不作为并行真源。

AC9. `.reasonix/` 不再出现在仓库跟踪文件中，`.gitignore` 包含 `.reasonix/`。

AC10. README / README_EN 不再宣称未实现的“API Key 加密存储”“全部 IndexedDB”“完整 ToolSelector 智能选择”或已删除的 `bh_iframe_click` / `bh_iframe_type` 主能力。

AC11. 最小安全回归测试覆盖 approval stale、sensitive trace、prompt injection、tool escape、`FORM_FILL_FIELD` validation、非表单 high-risk approval 语义、runtime message sender boundary、合法 JSON prompt 裁剪和 locale bootstrap。

AC12. README / README_EN / docs/tools 不再宣称不存在或不可执行的工具，不再误导用户“API Key 加密存储”或“完全不向云 provider 发送数据”。

AC13. Ask 模式的 prompt 和文档明确允许低风险观察性滚动，但禁止点击、输入、提交等业务 mutation。

AC14. 已有 v1.1 表单填写、verify、submit approval、waterfall、Debug drawer 主路径不发生行为回退。
