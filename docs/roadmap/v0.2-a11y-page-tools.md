# v0.2 — A11y Page Tools Prototype

## 1. 背景

v0.1 只能运行 mock loop，无法理解真实网页。BrowserHelm 的核心差异是 a11y-first 页面理解和 stable ref 操作，因此必须尽早建立 content script、page observation、accessibility-like tree、ref map 和基础 element actions。

当前用户遇到的问题：Agent 不能知道页面上有什么，也不能可靠点击或输入。

现有系统限制：没有真实页面观察，没有 ref_id 到 DOM node 的映射，也无法在 action 后确认页面是否变化。

为什么现在要做：v0.2 是 v1.0 表单/调试能力的页面执行基础。

## 2. 用户故事

US1. 作为浏览器用户，我希望 agent 能识别当前页面的按钮、输入框和链接，以便完成简单网页任务。

US2. 作为开发者，我希望每个可交互元素都有 stable ref_id，以便模型不需要猜 CSS selector。

US3. 当页面跳转或 DOM 更新导致 ref 失效时，作为 agent runtime，我希望能返回 REF_STALE 并触发重新观察，以便避免重复点击失效元素。

US4. 作为用户，我希望 click/type 后系统自动观察页面变化，以便 agent 不靠猜测继续下一步。

## 3. 目标

本 Issue 要完成：

- 建立 content script RPC。
- 实现 `bh_page_observe`。
- 实现 `bh_a11y_snapshot`、`bh_a11y_find_interactive`、`bh_a11y_resolve_ref`、`bh_a11y_refresh_refs`。
- 实现 `bh_element_click`、`bh_element_type_text`、`bh_element_set_value`、`bh_element_press_key`。
- 实现 `bh_nav_open_url` 和 `bh_viewport_scroll`。
- 实现 action 后 pageChanged / ref stale / mutation summary。

### 任务拆解

## 5. 产品方案

### 功能入口

通过 v0.1 agent loop 调用真实 page/a11y/element tools。

### 用户路径

任务开始 -> bh_page_observe -> bh_a11y_snapshot -> 模型选择 ref_id -> bh_element_click/type -> runtime 自动 observe -> 下一步。

### 正常状态

Observation 返回 URL、title、visible text summary、a11y tree、interactive refs。

### 空状态

页面无可交互元素时，返回 empty observation 和 reason。

### 错误状态

ref 不存在返回 REF_NOT_FOUND；DOM 变化后返回 REF_STALE；权限不允许注入返回 CONTENT_SCRIPT_UNAVAILABLE。

### 权限 / 可见性

需要 content script 注入 all_urls。chrome://、Chrome Web Store 等不可注入页面要明确提示。

## 7. 技术方案

### 现状

无真实页面工具。

### 目标设计

content script 提供 page/a11y/dom 能力，background 通过 RPC 调用。

### 数据流 / 调用链

AgentLoop -> ToolRouter -> BackgroundRPC -> ContentRPC -> page/dom module -> ToolResult -> Auto observe。

### 关键类型 / API

```ts
type ElementRef = {
  refId: string;
  role?: string;
  name?: string;
  tagName: string;
  visible: boolean;
  disabled?: boolean;
};

type Observation = {
  url: string;
  title: string;
  visibleText: string;
  interactiveRefs: ElementRef[];
  a11yTree: string[];
};
```

### 错误处理

所有 content RPC timeout、不可注入、ref stale、action blocked 都返回结构化 ToolResult。

### 复用与约束

优先复用：DOM APIs、dom-accessibility-api、统一 ToolResult。

不要重复实现：selector 猜测逻辑、RPC parser、ref lifecycle。

## 10. 验收标准

AC1. 覆盖 US1：当页面有按钮/输入框/链接时，bh_a11y_snapshot 返回可读结构和 ref_id。

AC2. 覆盖 US2：模型可以用 ref_id 执行 click/type，不需要 CSS selector。

AC3. 覆盖 US3：当 ref 不存在或 stale 时，系统返回明确错误并建议 re-observe。

AC4. 覆盖 US4：mutating tool 执行后 runtime 自动生成新的 observation summary。

AC5. 已有 v0.1 AgentLoop、ToolRegistry、TraceRecorder 行为不受影响。

AC6. 实际改动不超出「改动目录结构」；如必须超出，PR 需要写偏离说明。

AC7. 不涉及设计图，设计验收为不适用。
