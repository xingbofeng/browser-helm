# v1.1 — Assisted Form Fill + Frontend Debug

## 1. 背景

v1.0 已经能解释页面和表单问题，但还不能真正帮用户填写字段、执行 verify 和在提交前请求确认。用户接下来最需要的是“辅助填写，而不是盲目自动化”。

当前用户遇到的问题：虽然已经知道问题在哪里，但仍然要手工填写表单、逐个修正字段，也缺少提交前确认和更完整的 debug workspace。

现有系统限制：缺少 fill/verify/submit action、FormPanel、DebugPanel、trace detail 和 submit approval 流程。

为什么现在要做：v1.1 负责把只读诊断推进到“辅助填写 + 提交确认 + 更完整 debug UI”。

## 2. 用户故事

US1. 作为前端开发者，我希望 agent 能读取 console/network/form 状态，以便快速理解页面为什么坏了。

US2. 当用户准备提交表单时，作为用户，我希望系统先验证字段并请求确认，以便避免提交错误或敏感信息。

US3. 作为 QA，我希望 agent 能列出当前页面的表单字段、必填项和 validation errors，以便快速检查页面质量。

US4. 作为运营后台用户，我希望 agent 能帮助填写表单字段并解释 submit disabled 原因，以便减少重复操作和困惑。

US5. 当页面没有表单或没有错误时，作为用户，我希望系统明确告诉我当前页面健康状态，而不是显示空白。

## 3. 目标

本 Issue 要完成：

- 实现 form list/inspect/read/fill/verify/submit-with-approval。
- 实现 console errors/logs、network failures/summary、page health。

- 完成 v1.1 cockpit 扩展 UI：FormPanel、DebugPanel、TraceViewer。
- 完善本地 trace 和安全策略。

## 4. 不做什么

本 Issue 明确不处理：

- 不做长期 memory。
- 不做 workflow replay。
- 不做 CDP response body deep inspector。
- 不做 screenshot/vision。
- 不做 multi-tab、PDF、upload/download。
- 不做 domain adapters。

## 5. 产品方案

### 功能入口

用户在 Cockpit 输入“帮我检查这个页面为什么报错”“帮我验证这个表单”“帮我填这个表单”。

### 用户路径

Agent observe 当前页面 -> 读取 forms/debug signals -> 生成诊断 -> 可选填写字段 -> verify_form -> submit approval -> 执行提交 -> observe result。

### 正常状态

FormPanel 展示字段、当前值、required、disabled、validation。DebugPanel 展示 console errors、network failures、page health summary。

### 空状态

没有表单时显示“当前页面未检测到表单”。没有错误时显示“未发现 console/network 错误”。

### 错误状态

字段写入失败、submit 被阻止、content script unavailable、网络日志不可用都要给出原因和下一步建议。

### 权限 / 可见性

submit、send、publish、delete、payment 类动作必须 approval。password/token/API key 默认 mask。

## 7. 技术方案

### 现状

已有 v1.0 的 read-only diagnosis、基础 page/a11y/element tools 和 cockpit UI。

### 目标设计

Form/debug tools 主要在 content script 读取 DOM、forms、console/network summary；background 负责 trace 和 model turn；policy 层负责 submit approval 和 secret masking。

### 数据流 / 调用链

Task -> observe -> bh_form_list/bh_debug_collect_page_health -> model diagnosis -> optional bh_form_fill_field -> bh_form_verify -> bh_form_submit_with_approval -> approval -> submit -> observe。

### 关键类型 / API

```ts
type FormFieldSnapshot = {
  refId: string;
  label?: string;
  name?: string;
  type: string;
  valuePreview: string;
  required: boolean;
  disabled: boolean;
  validationMessage?: string;
  sensitive: boolean;
};

type PageHealth = {
  consoleErrors: ConsoleErrorSummary[];
  networkFailures: NetworkFailureSummary[];
  forms: FormSummary[];
};
```

### 错误处理

submit 前 verify 失败要阻断提交。敏感字段只显示 mask preview。网络和 console 收集失败不应阻断 form tools。

### 复用与约束

优先复用：v0.2 ref map、v0.33 action readiness、v0.4 approval dialog、TraceEvent。

不要重复实现：element typing、risk classification、tool result contract。

## 10. 验收标准

AC1. 覆盖 US1：当前端页面有 console 或 network 错误时，系统会收集并解释错误，展示可行动的 debug summary。

AC2. 覆盖 US2：当用户准备提交表单时，系统会先执行 verify_form，并在 approval dialog 中展示提交动作和字段摘要。

AC3. 覆盖 US3：当页面存在表单时，FormPanel 展示字段、required、disabled、validation 状态。

AC4. 覆盖 US4：当 submit button disabled 时，系统会尝试解释 disabled 原因。

AC5. 覆盖 US5：当页面无表单或无错误时，UI 展示明确空状态。

AC6. 已有 v0.x 行为不受影响。

AC7. 实际改动不超出「改动目录结构」；如必须超出，PR 需要写偏离说明。

AC8. 如涉及设计图，实现结果符合「设计图 / 视觉参考」中列出的范围和关键视觉要求。
