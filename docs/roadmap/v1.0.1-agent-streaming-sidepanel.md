# v1.0.1 — Agent Streaming Side Panel

## 1. 背景

v1.0 已经把 BrowserHelm 的首发产品边界收敛为“页面检查员 + 表单医生”：先看懂页面，再解释问题，默认只读，必要时通过 HITL / Policy / Approval Runtime 保护高风险动作。v0.4 Cockpit UI 也已经把页面观察、Ref 映射、交互元素、表单字段、工具结果、Trace 和 Settings 都放进 side panel。

但当前 Cockpit 仍然更像开发者数据驾驶舱，而不是一个真实产品用户愿意长期使用的 Agent 面板。四个一级 Tab 暴露了过多内部数据，`ref_id`、raw trace、tool result 和字段表格混在主体验里，普通用户很难判断自己应该看哪里，也容易误以为 BrowserHelm 是调试工具而不是页面 Agent。

当前用户遇到的问题：

- 打开 side panel 后，主视角是“数据 Tab”，不是“BrowserHelm 正在帮我检查页面”。
- 页面摘要、表单诊断、证据和建议分散在不同面板中，用户需要自己拼结论。
- 旧 Debug 数据对开发者有用，但对 v1.0 产品用户过载。
- 真实 Agent 体感不足；用户看不到模型和工具正在连续工作。
- 模型配置入口不够产品化，API Key / Base URL / Model / streaming 开关应该从主 Debug 中抽离。

为什么现在要做：v1.0.1 是 v1.0 发布体验的产品化修正版本。它不扩大 BrowserHelm 的浏览器能力边界，不做自动填写和多轮聊天，而是把已有能力重新组织为“单 Agent 面板 + 真实 streaming + 精简 Debug + 本地模型配置”。同时，这个版本必须清理旧 Cockpit UI 中不再使用的代码，避免 v1.0.1 之后同时维护两套信息架构。

## 2. 用户故事

US1. 作为普通用户，我希望打开 BrowserHelm 后看到一个 Agent 正在观察、诊断并给出建议，而不是先看到四个数据 Tab。

US2. 作为用户，我希望页面摘要始终能被看见，以便确认 BrowserHelm 正在理解正确的页面。

US3. 作为用户，我希望模型回复能真实流式出现，以便知道 BrowserHelm 正在工作，而不是卡住。

US4. 作为用户，我希望工具执行、页面观察、诊断完成和错误恢复能以自然语言状态出现，而不是原始 trace。

US5. 作为开发者，我希望必要时展开高级开发者选项，查看 Trace、工具结果、元素与表单映射和 Streaming 状态，以便排障。

US6. 作为开发者，我希望 Ref、交互元素和表单字段合成一张可筛选表，以便减少重复视图，提高定位效率。

US7. 作为用户，我希望右上角三个点可以打开模型配置弹窗，配置 API Key、Base URL、Model 和 streaming 开关。

US8. 作为用户，我希望可以测试模型连接，以便知道配置是否可用、是否支持 streaming。

US9. 作为安全敏感用户，我希望 API Key 只保存在本地扩展存储，不进入 Trace、页面摘要、Debug 截图或 Agent 消息。

US10. 作为维护者，我希望不再使用的旧 UI 组件、旧 Tab 入口和重复状态代码被删除，而不是隐藏或注释掉。

US11. 作为 QA，我希望刷新 side panel 后仍能恢复当前 Agent 消息、已生成内容和 Debug 状态，而不是丢失 streaming 过程。

US12. 作为开发者，我希望 streaming 失败时自动 fallback 到非流式完成模式，并能在 Debug 中看到 fallback 原因。

## 3. 目标

本 Issue 要完成：

- 将 side panel 默认体验改为 BrowserHelm Agent 聊天瀑布流。
- 产品名统一显示为 `BrowserHelm`，不再使用 `BrowserHelm Cockpit` 作为首屏标题。
- 保留当前输入栏交互：左侧 mode 胶囊下拉、中心任务输入、右侧 lucide `Send` 图标按钮。
- 默认打开 side panel 时自动启动一次 readonly 页面观察 run，用于生成页面摘要和第一屏 Agent 状态。
- 引入可恢复的 `AgentMessage` 产品层消息模型，并写入 `RunSnapshot`。
- 实现 OpenAI-compatible provider 的真实 token/chunk streaming。
- 工具执行和 runtime 生命周期使用 event streaming；普通 UI 显示产品化状态，Debug 才显示内部事件。
- streaming 启动失败或中途失败时 fallback 到原 `complete()` 路径。
- Debug 的 Streaming Tab 展示 provider/model、streaming enabled、fallback、chunk count、duration、start/finish/error 摘要和最终合并文本。
- 右上角三个点打开模型配置弹窗，支持 API Key、Base URL、Model、Streaming 开关、测试连接。
- Provider 配置只保存到本地浏览器扩展存储；API Key 默认 mask，不进入 trace/message/debug payload。
- 真实引入 `animal-island-ui` 作为 UI 依赖；能覆盖的控件优先使用，业务组件不足时参考其视觉自写。
- 使用 lucide 图标补齐发送、更多、Debug、工具、Trace、Streaming、关闭、显示/隐藏 Key 等图标。
- “高级开发者选项”默认折叠，Debug 展开状态可本地记忆。
- Debug 只保留四个 Tab：Trace、工具、元素与表单、Streaming。
- 将 Ref 映射、交互元素和表单字段合并为一张“元素与表单”表。
- 删除不再使用的旧四 Tab 产品入口、旧 Cockpit 布局分区、重复 Settings 入口和无引用组件代码。
- 更新 UI、runtime、provider、schema、store、E2E/POM 和文档测试。
- 更新 `implementation-notes.md` 记录本次 v1.0.1 的设计决策和代码清理原则。

## 4. 不做什么

本 Issue 明确不处理：

- 不做完整多轮聊天；v1.0.1 只支持单次任务 Agent 流程。
- 不做跨 run 长期记忆。
- 不做 conversation list、message database 或会话管理。
- 不做自动填写、批量填写、自动提交。
- 不做新的高风险动作能力。
- 不做 workflow replay。
- 不做 screenshot / vision。
- 不做 DevTools CDP deep inspector。
- 不做 sub-agent / agent-as-tool / delegate_to_agent。
- 不做所有 provider 的 streaming 适配；v1.0.1 只承诺 OpenAI-compatible。
- 不做云同步、账号系统、团队配置或远程 key vault。
- 不把每个 token 都写入完整 Trace 日志。
- 不把旧四 Tab 隐藏后继续维护；确认不用的旧代码必须删除。

## 5. 产品方案

### 功能入口

用户打开 BrowserHelm side panel，进入一个单 Agent 面板。首屏不再显示四个一级数据 Tab，而是显示：

- 顶部 BrowserHelm 标题和页面状态。
- 页面摘要 / 当前页面卡。
- Agent 聊天瀑布流。
- 底部任务输入栏。
- 右上角三个点模型配置入口。
- 底部或末尾“高级开发者选项”折叠入口。

### 用户路径

打开 side panel -> BrowserHelm 自动 readonly 观察当前页面 -> Agent 消息显示“正在观察当前页面” -> 页面摘要出现 -> 用户输入任务 -> 模型文本 token/chunk streaming -> 工具事件以自然语言状态追加 -> 诊断结论和建议出现 -> 用户可展开 Debug 查看 Trace / 工具 / 元素与表单 / Streaming。

### 正常状态

默认 UI 只展示产品化内容：

- 当前页面标题、域名、页面摘要和 warning。
- Agent 正在做什么。
- 表单或页面问题结论。
- 证据摘要和建议。
- fallback 提醒使用自然语言表达，例如“生成时遇到网络波动，已重新完成诊断”。

Debug 才展示内部状态：

- `model_stream_started`、stream chunk summary、`model_stream_finished`、`model_stream_failed`。
- `tool_started`、`tool_result`。
- raw trace payload 的脱敏预览。
- 元素和表单映射表。

### 空状态

没有页面数据时，默认 UI 显示“等待观察当前页面”或“当前页面暂时不可观察”，并提供可读原因。模型未配置时，显示轻量设置引导，点击右上角三个点进入模型配置弹窗。

没有表单时，Agent 结论说明“当前页面未检测到表单”，Debug 的“元素与表单”表仍可显示按钮、链接和其他交互元素。

### 错误状态

content script unavailable、provider 未配置、streaming 失败、fallback 失败、模型响应格式错误、tool failure、权限缺失都必须显示：

- 默认 UI：用户能理解的错误说明和下一步操作。
- Debug：错误码、trace event、fallback 原因、provider/test connection 状态。

### 权限 / 可见性

API Key 默认 mask。完整 API Key 不允许进入：

- `RunSnapshot.messages`
- `RuntimeEvent.payload`
- Trace preview
- Debug Streaming tab
- 页面摘要
- 截图文案
- 测试快照

Debug 默认关闭。开发者打开后，本地记忆展开状态。`debug` mode 或错误卡片可以提供“查看调试信息”入口。

## 7. 技术方案

### 现状

当前 UI 通过 `CockpitApp` 组合 `ChatPanel`、四个数据 Tab、`StepTimeline`、`TraceLog`、`DiagnosisOverview`、`ToolInspector`、`ApprovalDrawer` 和 `SettingsPanel`。`RuntimePort.subscribeRun` 已经存在，side panel 当前收到事件后主要通过 `getRunSnapshot()` 刷新。`ModelClient.complete()` 当前是一次性返回文本，`OpenAICompatibleClient` 使用 `/chat/completions` 非流式请求。

### 目标设计

v1.0.1 将 runtime 内部 trace 与产品 UI message 分离：

- Trace 是 Debug 数据。
- `AgentMessage[]` 是默认 UI 的稳定输入。
- Streaming chunk 更新当前 `AgentMessage.content`。
- 工具事件更新产品化状态消息，也记录 Debug trace。

UI 不直接调用 `AgentLoop`、`ToolRouter` 或 provider client。Side panel 仍通过 `RuntimePort` 与 background/runtime 通信。Provider 配置仍通过 settings store 保存。

### 数据流 / 调用链

自动观察：

```txt
SidePanel open
-> RuntimePort.startRun({ task: '观察当前页面', mode: 'ask', tabId })
-> RunManager observeInitial
-> tool event streaming
-> RunSnapshot.messages update
-> Agent waterfall render page summary
```

用户任务：

```txt
Chat input submit
-> RuntimePort.startRun({ task, mode, tabId })
-> RunManager / AgentLoop
-> ModelClient.streamComplete if enabled
-> model_stream_* events
-> AgentMessage streaming update
-> fallback complete if stream fails
-> final DebugReport / findings
```

Debug 展开：

```txt
RunSnapshot.trace + toolResult + structuredPageData + streaming metadata
-> Debug drawer
-> Trace / 工具 / 元素与表单 / Streaming tabs
```

模型配置：

```txt
MoreHorizontal button
-> ModelConfigModal
-> settings store save
-> Runtime/provider test connection API
-> masked status render
```

### 关键类型 / API

```ts
type AgentMessageRole = 'user' | 'agent' | 'system';

type AgentMessageStatus = 'streaming' | 'complete' | 'error';

type AgentMessageKind =
  | 'task'
  | 'page_summary'
  | 'agent_status'
  | 'diagnosis'
  | 'recommendation'
  | 'error';

type AgentMessage = {
  id: string;
  role: AgentMessageRole;
  kind: AgentMessageKind;
  status: AgentMessageStatus;
  title?: string;
  content: string;
  createdAt: number;
  updatedAt: number;
  debugEventIds?: string[];
};

type StreamingState = {
  enabled: boolean;
  active: boolean;
  provider?: string;
  model?: string;
  chunkCount: number;
  fallbackUsed: boolean;
  fallbackReason?: string;
  finalText?: string;
  startedAt?: number;
  finishedAt?: number;
};

type RunSnapshot = {
  // existing fields...
  messages?: AgentMessage[];
  streaming?: StreamingState;
};

type ProviderSettings = {
  apiKey?: string;
  baseUrl: string;
  model: string;
  streamingEnabled?: boolean;
};

type ProviderTestResult = {
  ok: boolean;
  code: string;
  message: string;
  supportsStreaming?: boolean;
  model?: string;
};
```

Runtime event 命名建议：

```ts
model_stream_started
model_stream_delta
model_stream_finished
model_stream_failed
model_stream_fallback_started
model_stream_fallback_finished
provider_test_started
provider_test_finished
provider_test_failed
```

Trace 策略：

- 不记录每个 token 的完整 payload。
- 可记录 delta summary、chunk count、长度、耗时和最终文本摘要。
- 完整最终文本可存在 `AgentMessage.content` 和 Debug Streaming final preview。
- API Key 永不记录。

### 错误处理

streaming 错误分三类：

- 启动前失败：直接 fallback 到 `complete()`。
- 中途失败且没有完整可解析结果：fallback 到 `complete()`。
- fallback 也失败：进入 run error，并显示 provider/model/网络/响应格式错误。

UI 错误分层：

- 主 UI：人类可读说明。
- Debug：错误码、事件、fallback reason、sanitized payload。

### 复用与约束

优先复用：

- `RunSnapshot`
- `RuntimePort`
- `TraceLog`
- `ToolInspector`
- `StructuredPageData`
- `SettingsPanel` 的数据保存逻辑
- `ApprovalDrawer`
- `Mode system`
- `TaskClassifier`
- `ToolSelector`

必须删除：

- 旧四 Tab 的产品一级导航入口。
- 不再被 Debug 使用的旧 tab wrapper、旧布局容器和旧 CSS。
- 重复 Settings 面板入口。
- 无引用组件、无引用 store 字段和无效测试 selector。

不要删除：

- 仍被 Debug 合并表复用的数据转换逻辑。
- 仍被 tests/e2e 或 legacy side panel 明确引用的兼容入口，除非同步迁移测试。
- Approval 相关 UI 和 policy runtime。

依赖风险：

`animal-island-ui` npm 包可安装并提供 Button/Input/Switch/Modal/Card/Collapse 等基础组件，但其 README/站点存在“个人学习、研究与非商业展示”说明，和 npm / package license 的 MIT 表述需要发布前复核。v1.0.1 技术上可以引入，产品发布前必须确认授权边界；如果授权不可接受，应保留 BrowserHelm 自写组件 fallback。

## 9. 依赖关系

前置依赖：

- v0.4 Cockpit UI 的 RuntimePort、sidepanel entrypoint、settings store、approval UI。
- v1.0 Page Inspector + Form Doctor 的 mode system、ToolSelector、RecoveryPolicy、AgentFinding、DebugReport、structured page data。
- 现有 Chrome extension debug SOP 和 E2E POM 分层。

新增依赖：

- `animal-island-ui`：基础 Button/Input/Switch/Modal/Card/Collapse/Tabs 类视觉控件。
- `lucide-react`：已在项目中使用时继续复用；若未安装，新增前确认包体和 tree-shaking。

授权依赖：

- `animal-island-ui` 发布前需要复核许可证与 README 非商业说明冲突。
- 如果不能用于 BrowserHelm 发布版，必须切换为 BrowserHelm 自写组件，保留同等视觉风格。

实现依赖：

- OpenAI-compatible provider 必须支持 SSE 格式或 fallback。
- Chrome extension messaging 需要支持订阅事件和 snapshot 恢复。
- UI CSS 需要限定作用域，避免 `animal-island-ui/style` 污染 extension 其他页面。

后续版本依赖：

- v1.1 可在 `AgentMessage` 基础上做完整多轮聊天和用户插话。
- v1.2 可在 message/trace 基础上做长期 memory 和 workflow replay。
- v1.3+ 可在 Debug 数据基础上做 eval、trace replay 和 DevTools deep panel。

## 10. 验收标准

AC1. 打开 side panel 后，默认首屏显示 BrowserHelm Agent 瀑布流，不显示旧四个产品一级 Tab。

AC2. side panel 打开后会自动 readonly 观察当前页面；页面摘要进入 Agent 消息和页面摘要卡。

AC3. 输入栏保留当前胶囊 mode 下拉、任务输入和绿色发送按钮，并且 100% 适配 side panel 宽度。

AC4. 右上角三个点可以打开模型配置弹窗，支持 API Key、Base URL、Model、Streaming 开关、测试连接、保存和取消。

AC5. API Key 默认隐藏；完整 Key 不出现在 DOM 文案、trace payload、Debug tab、AgentMessage、测试快照或截图中。

AC6. OpenAI-compatible provider 在 streaming enabled 时使用真实 token/chunk streaming。

AC7. streaming disabled 时走非流式 `complete()`。

AC8. streaming 启动失败或中途失败时 fallback 到 `complete()`；fallback 失败才进入 run error。

AC9. Debug 的 Streaming Tab 能显示 streaming enabled、active、chunk count、fallbackUsed、fallbackReason、duration、final preview。

AC10. `RunSnapshot.messages` 可恢复；side panel 刷新后能恢复用户任务、页面摘要、已生成 Agent 内容和完成状态。

AC11. Debug 默认折叠；展开后只显示 Trace、工具、元素与表单、Streaming 四个 Tab。

AC12. 元素与表单 Tab 使用一张合并表展示 Ref / 交互元素 / 表单字段，支持搜索和 chips：全部、表单字段、按钮、异常、禁用。

AC13. 表格敏感值显示 `[MASKED]`；password/token/API key 不展示真实值。

AC14. Trace Tab 不把每个 token 作为完整 trace 行刷屏；只展示 stream lifecycle 和 summary。

AC15. 工具 Tab 能展示最新工具结果、错误码、summary、flags 和脱敏详情。

AC16. 默认 UI 不出现 raw JSON、`ref_id`、chunk、trace payload；这些只在 Debug 中出现。

AC17. 旧四 Tab 产品导航、旧 Cockpit 标题和无用旧布局代码被删除或迁移，不允许仅用 CSS 隐藏。

AC18. 删除旧代码后，`rg` 不应出现无引用的旧 CSS class、旧测试 selector 或旧组件导入。

AC19. `animal-island-ui` 只在 sidepanel UI 边界引入；若样式冲突，必须改为 wrapper 限定或自写组件。

AC20. 测试连接成功时显示“连接正常”和 streaming 支持状态；失败时显示可读错误，不启动 Agent run。

AC21. 模型未配置时，主 UI 给出设置引导；Debug 显示 provider 未配置，但不显示 key。

AC22. `npm run typecheck` 通过。

AC23. `npm run lint` 通过。

AC24. 相关 node/ui/runtime/provider 单测通过。

AC25. extension side panel 相关 E2E 或 browser integration 测试通过。

AC26. 使用 `npm run build` 成功构建 Chrome MV3 扩展。

AC27. 使用 Chrome for Testing debug SOP 截图验证 Agent 默认态、Debug 展开态、模型配置弹窗。

AC28. `implementation-notes.md` 记录 v1.0.1 的设计决策、偏差说明、权衡分析和旧代码清理结果。
