# v1.7 — Runtime Quality + Full i18n Hardening

## 1. 背景

v1.1.2 先修 AgentLoop 主链路安全，v1.2 到 v1.6 继续补 memory、CDP、vision、高级工具和 domain adapters。等这些能力稳定后，需要回头整理完整 Mode System、ToolSelector、任务完成判断、用户可见文案和 tool/error i18n，避免产品能力越来越多但 runtime 策略分散。

当前用户遇到的问题：不同 mode 的工具可见性、权限、风险、恢复和完成判断分散在多个模块；部分 tool summary、error、debug 文案仍然硬编码中英文，导致 UI 语言不一致。

现有系统限制：v1.0 的 Mode System 和 v1.1.2 的最小 ToolSelector/权限边界能支撑主链路，但还不是完整重写；i18n 先修 locale bootstrap 和主界面关键文案，未覆盖全部 tool summary/error/debug 文案。

为什么现在要做：在高级工具和 domain adapters 之后，工具面和模式复杂度会上升，需要一次 runtime quality hardening，把策略层、完成判断和本地化统一起来。

## 2. 用户故事

US1. 作为用户，我希望 agent 自动选择 Ask/Form/Debug/Act/Advanced/Memory 等模式时行为一致，以便减少误判和越权。

US2. 作为用户，我希望 agent 知道任务是否完成，而不是只依赖模型自己说 finish。

US3. 作为非中文或非英文用户，我希望主要 UI、tool summary、error 和 approval 文案跟随我的语言设置。

US4. 作为开发者，我希望 Mode System、ToolSelector、RecoveryPolicy、Goal/SuccessCriteria 和 i18n 都有统一测试，以便新增工具时不破坏既有策略。

## 3. 目标

本 Issue 要完成：

- 完整 Mode System 重写或系统性收敛：TaskClassifier、ToolSelector、ContextPolicy、RecoveryPolicy、Goal/SuccessCriteria、Permission/Capability 统一编排。
- 完整 ToolSelector：根据 mode、task、state、permission、risk、domain policy、adapter guidance 和 recovery phase 裁剪工具。
- Goal/SuccessCriteria 产品化：启动入口接收目标和验收标准，finish 判断参考工具结果、plan progress 和 success criteria。
- 全面 i18n tool summary/error/debug 文案：用户可见文案使用 i18n key，内部 trace code 保持稳定枚举。
- i18n hardcoded checklist 收敛：清理主界面、approval、tool detail、debug drawer、settings 中的用户可见硬编码文案。
- 建立 runtime strategy regression tests，覆盖 mode selection、tool visibility、finish criteria、locale rendering。

### 任务拆解

- T1. 盘点现有 Mode System、ToolSelector、RecoveryPolicy、Goal/Plan、Capability/Permission 的重复边界。
- T2. 定义 `RuntimeStrategy` / `ModePolicy` 契约，统一输入 task、mode、page state、permission、risk 和 recovery phase。
- T3. 重写或收敛 ToolSelector，使工具暴露规则从静态 mode list 升级为策略决策。
- T4. 将 Goal/SuccessCriteria 接入 run 启动、plan progress、finish decision 和 user-visible summary。
- T5. 增加完成判断测试：表单填完但未要求提交、debug 找到根因、长页面总结完成、workflow replay 完成。
- T6. 定义用户可见文案边界：UI summary、tool summary、error、approval、debug explanation 进入 i18n；内部 trace/event code 不翻译。
- T7. 将 tool summary/error/debug drawer/settings 逐步迁移到 i18n key。
- T8. 更新 i18n hardcoded checklist 并作为后续 lint/test 输入。
- T9. 增加 locale rendering 测试，覆盖 zh/en 以及 fallback locale。
- T10. 更新 docs/prompts.md、docs/tool-system.md、docs/security.md 中的 mode/i18n 边界。

## 4. 不做什么

本 Issue 明确不处理：

- 不新增 CDP、vision、高级浏览器工具或 domain adapter 能力。
- 不改 v1.1.2 已稳定的 Prompt ABI 安全边界。
- 不把内部 trace code、schema enum、error code 全部翻译。
- 不做云端翻译或用户自定义翻译平台。
- 不引入复杂 multi-agent team。

## 5. 产品方案

### 功能入口

用户仍通过 Cockpit 输入任务；runtime 在后台选择 mode、tools、context 和 completion criteria。Settings 中展示语言设置和可选的策略调试信息。

### 用户路径

任务开始 -> RuntimeStrategy 选择 mode/tools/context -> Agent 执行 -> Goal/SuccessCriteria 检查完成度 -> 用户看到本地化 summary/error/approval。

### 正常状态

不同模式下只暴露必要工具；用户语言设置稳定生效；完成判断清楚说明“已完成什么”和“还缺什么”。

### 空状态

没有明确 success criteria 时，使用 mode 默认 completion heuristic，并在 Debug detail 中说明判断依据。

### 错误状态

mode 冲突、权限不足、工具不可见、success criteria 不满足、locale 缺 key 都必须有 fallback 和测试覆盖。

### 权限 / 可见性

Mode System 不能绕过 PolicyEngine。i18n 只影响展示语言，不影响 policy、risk、approval 或 schema 枚举。

## 7. 技术方案

### 现状

v1.1.2 提供安全边界和最小 ToolSelector；v1.2-v1.6 会继续增加 memory、workflow、CDP、高级工具和 adapters。当前缺少统一 runtime strategy 层和完整 i18n 文案治理。

### 目标设计

新增或收敛 `RuntimeStrategy` 作为 AgentLoop 每轮的策略入口，输出 selected mode、available tools、context policy、recovery budget、goal progress 和 completion hints。用户可见文案通过 i18n keys 渲染，trace/event code 保持稳定英文枚举。

### 数据流 / 调用链

Task + page state + permission + memory/adapter state -> RuntimeStrategy -> ToolSelector + ContextPolicy + RecoveryPolicy + GoalEvaluator -> AgentLoop -> localized UI summary。

### 关键类型 / API

```ts
type RuntimeStrategyInput = {
  task: string;
  explicitMode?: RunMode;
  pageState?: unknown;
  permissionState?: unknown;
  recoveryPhase?: string;
  successCriteria?: string[];
};

type RuntimeStrategyDecision = {
  mode: RunMode;
  availableTools: string[];
  contextPolicyId: string;
  recoveryBudget: Record<string, number>;
  completionHints: string[];
  userVisibleReasonKey: string;
};
```

### 错误处理

策略决策失败时回退 Ask/read-only mode，并说明原因。缺少 i18n key 时显示 fallback 文案并记录 dev warning，不阻断用户任务。

### 复用与约束

优先复用：v1.1.2 Prompt ABI、ToolSelector、PolicyEngine、i18n locale bootstrap、Goal/Plan schema。

不要重复实现：ToolRouter、ApprovalManager、ContextCompactor、existing i18n provider。

## 10. 验收标准

AC1. RuntimeStrategy 能基于 task/mode/state/permission/risk 输出稳定的 mode、tools 和 context policy。

AC2. ToolSelector 不再只依赖静态 mode list，能解释工具被隐藏或暴露的原因。

AC3. Goal/SuccessCriteria 参与 finish 判断，并在用户可见 summary 中说明完成状态。

AC4. 用户可见 tool summary、error、approval 和 debug explanation 使用 i18n key 渲染。

AC5. zh/en/fallback locale 渲染通过测试，缺 key 不会导致 UI 崩溃。

AC6. Mode System 不能绕过 PolicyEngine 或 approval policy。

AC7. 已有 v1.1.2 Prompt ABI、安全回归和 v1.2-v1.6 主链路不受影响。
