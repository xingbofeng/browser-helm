# v1.0.2 — v1.0 Required Tools + Long Page / Iframe Reading + Agent Loop Tooling

## 1. 背景

v1.0.1 已经把 BrowserHelm 产品化为单 Agent side panel，并接入真实 provider streaming。但当前运行链路仍有一个关键断层：side panel 用户任务主要由 `RunManager` 先做一次 `bh_page_observe`，再把裁剪后的 snapshot 摘要交给 provider 生成回答；provider 回答本身不是一个会持续调用工具的真实 AgentLoop。

这导致长页面场景下出现明显问题：`bh_page_observe` 是 bounded observation，`visibleTextSummary` 默认会截断，完整 `ToolResult.data` 又不会进入模型上下文。页面很长、有很多正文、内容在 iframe 内、或者滚动后才 lazy-load 时，Agent 很容易只基于第一页摘要回答，而且没有可用工具继续读取。

v1.0.2 的目标是一次性补齐 v1.0 必须工具缺口，同时完成长页面与 iframe 读取闭环，并把用户任务接入真实 AgentLoop / tool-calling 路径。这个版本不追求表单提交或复杂浏览器自动化，但会把 v1.0 规划中已经承诺的 read-only / low-risk 工具面补完整。

## 2. 用户故事

US1. 作为用户，我希望页面很长时，BrowserHelm 不要只看开头摘要就回答，而是能继续读取后续内容。

US2. 作为用户，我希望文档、博客、新闻、README 等正文页面能优先读取主内容区域，而不是被导航、页脚和按钮噪声淹没。

US3. 作为用户，我希望内容在 iframe 内时，BrowserHelm 能列出 iframe 并读取指定 iframe 的文本、摘要和滚动状态。

US4. 作为用户，我希望 iframe 内也能滚动读取，而不是只滚顶层页面。

US5. 作为用户，我希望页面需要滚动触发 lazy-load 时，BrowserHelm 能滚动、等待稳定、再重新观察或读取。

US6. 作为开发者，我希望滚动工具明确标记为会改变 viewport 的低风险动作，并要求后续重新 observe/read。

US7. 作为 Agent 维护者，我希望 provider 任务进入真实 AgentLoop 工具调用路径，而不是只能基于一次 snapshot 摘要生成回答。

US8. 作为安全敏感用户，我希望完整页面文本仍按上下文策略裁剪，不把整页 DOM、敏感字段或 raw trace 直接塞进模型。

US9. 作为 QA，我希望 trace 能看出 Agent 是因为 `VISIBLE_TEXT_TRUNCATED`、`hasMore` 或 iframe scroll 状态而继续读取。

US10. 作为维护者，我希望工具命名和 mode/risk 边界继续遵守 `bh_` 协议与现有 ToolSpec 规范。

## 3. 目标

本 Issue 要完成：

- 一次性补齐 v1.0 必须工具缺口：page read、element inspect/focus、nav、debug、policy。
- 提前纳入 viewport 读取闭环：`bh_viewport_get_info`、`bh_viewport_scroll`。
- 统一 iframe 工具为 `bh_iframe_list` 和 `bh_iframe_read`。
- 删除 `bh_frame_list`、`bh_iframe_click`、`bh_iframe_type`；不保留 deprecated 工具。
- iframe 内元素动作统一迁移到 `bh_element_click` 和 `bh_element_type_text`，由 stable ref / resolver 处理元素所在 iframe 上下文。
- `bh_viewport_scroll` 同时支持 top page 和 iframe target，不单独新增 `bh_iframe_scroll`。
- 明确 `bh_viewport_get_info` 为只读 safe 工具；`bh_viewport_scroll` 为 low risk，`changedPage: true`，`requiresObserve: true`。
- `bh_iframe_read` 支持读取指定 iframe 的 summary / visible text / article-like content，并返回 iframe 内 viewport/scroll 状态。
- `bh_page_observe` 在截断时给出面向 Agent 的 next hints，提示继续调用 page read / article / viewport 工具。
- 真实用户任务接入 AgentLoop/tool-calling，让模型可以根据工具结果继续调用读取、滚动、等待稳定、frame read 等工具。
- provider streaming 与 AgentLoop 决策兼容：工具调用阶段仍可通过消息/trace 表达，最终回答仍可 streaming。
- ContextCompactor 继续只给模型 summary/chunk，不把完整页面原始数据无界注入上下文。
- 更新 `src/tools/README.md`、tool constants、content RPC schema、runtime messages、测试与 roadmap。

## 4. 不做什么

本 Issue 明确不处理：

- 不做自动填写、自动提交或 submit-with-approval。
- 不新增 `bh_iframe_scroll`；iframe 滚动统一由 `bh_viewport_scroll({ target: "iframe", iframeId })` 承担。
- 不做 screenshot-first 或 vision full page capture。
- 不做 CDP DOM snapshot / response body deep inspector。
- 不做完整 PDF、下载文件、shadow DOM deep reader。
- 不做长期 memory、workflow replay 或 scratchpad 持久化。
- 不做 sub-agent / agent-as-tool / multi-agent。
- 不保留 `bh_iframe_click` / `bh_iframe_type` deprecated 兼容工具；测试场景必须迁移到 element actions。
- 不把完整 DOM 或无限长全文直接放进模型上下文。
- 不承诺能读取跨域 iframe 的受限 DOM；受浏览器安全边界限制时必须返回结构化 limitation。

## 5. 产品方案

### 功能入口

用户仍从 BrowserHelm side panel 输入任务。Agent 首先观察页面；如果观察摘要提示内容截断、页面可滚动、或任务明显依赖正文内容，则 Agent 自动调用读取工具继续获取上下文。

### 普通长页面路径

```txt
bh_page_observe
-> warnings includes VISIBLE_TEXT_TRUNCATED
-> bh_page_read_article 或 bh_page_read_visible_text
-> hasMore=true 时继续用 nextCursor 读取
-> 汇总证据并回答用户
```

### lazy-load 页面路径

```txt
bh_page_observe
-> bh_viewport_get_info({ target: "page" })
-> bh_viewport_scroll({ target: "page", direction: "down", amount: "page" })
-> bh_page_wait_until_stable
-> bh_page_observe 或 bh_page_read_visible_text
-> 回答用户
```

### iframe 内容路径

```txt
bh_iframe_list
-> bh_iframe_read({ iframeId, mode: "visible_text" })
-> 如果 iframe 内 canScrollDown 或 hasMore
-> bh_viewport_scroll({ target: "iframe", iframeId, direction: "down", amount: "page" })
-> bh_page_wait_until_stable
-> bh_iframe_read({ iframeId, mode: "visible_text" })
-> 回答用户
```

### 用户可见状态

默认 UI 用自然语言表达：

- 正在读取较长页面内容。
- 页面摘要被截断，正在继续读取正文。
- 检测到 iframe，正在读取嵌入内容。
- 已滚动页面并等待内容稳定。
- 当前 frame 受浏览器权限限制，无法读取内部 DOM。

Debug 中展示：

- tool name、args 脱敏摘要。
- cursor / nextCursor / hasMore。
- iframeId / iframe URL；Debug 可显示底层 frameId 作为 runtime id。
- scroll before / after。
- warnings / limitations。

## 7. 技术方案

### 现状

当前 `bh_page_observe` 会通过 content RPC 构建 bounded observation。`readVisibleText` 默认限制文本长度，并通过 `VISIBLE_TEXT_TRUNCATED` warning 表达截断。`ToolResult.data` 不进入模型上下文，`ContextCompactor` 只保留 summary。v1.0.1 的 provider 回复主要使用 `providerPrompt(record.task, snapshot)`，没有让用户任务进入真实可迭代工具调用 loop。

### 目标设计

v1.0.2 后，页面读取能力分为三层：

```txt
observe: 快速页面摘要和 refs
read: 按需读取正文/可见文本/iframe 文档
viewport: 获取滚动状态和执行低风险滚动
```

Agent 执行分为两个阶段：

```txt
tool-calling phase: AgentLoop 使用结构化 JSON 决策调用工具
answer phase: 基于读取后的 compacted context 生成用户可读回答，可继续 streaming
```

### 工具契约

`bh_viewport_get_info` 是 safe read-only 工具：

```ts
type ViewportTarget = {
  target?: 'page' | 'frame';
  frameId?: number;
};
```

`bh_viewport_scroll` 是 low risk viewport mutation：

```ts
type ViewportScrollArgs = {
  target?: 'page' | 'iframe';
  iframeId?: string;
  direction: 'up' | 'down' | 'left' | 'right';
  amount: 'half' | 'page' | 'end' | { pixels: number };
};
```

规则：

- `target` 默认为 `page`。
- `target === "iframe"` 时 `iframeId` 必填。
- `target === "page"` 时不允许传 `iframeId`，避免歧义。
- scroll result 必须 `changedPage: true`、`requiresObserve: true`。

`bh_iframe_read` 读取 iframe 文档，而不是单个 ref 元素：

```ts
type IframeReadArgs = {
  iframeId: string;
  mode?: 'summary' | 'visible_text' | 'article';
  cursor?: string;
  maxChars?: number;
  includeLinks?: boolean;
  linkLimit?: number;
};
```

`includeLinks` 默认开启，`linkLimit` 默认 30。Agent 可以通过分页和后续 cursor 继续读取更多相关 links；单次调用不得无界返回全站链接。

### AgentLoop 接入

必须完成以下行为：

- `RunManager.startRun()` 对用户任务创建真实 AgentLoop run，而不是只 schedule provider snapshot answer。
- AgentLoop 可见工具来自 ToolSelector，并包含本版本新增读取工具。
- 模型输出仍走严格 decision schema；需要最终自然语言回答时使用 finish/message 或单独 answer phase。
- 如果模型配置支持 streaming，最终回答 streaming；工具决策 JSON 不要求 streaming。
- 如果 AgentLoop 失败，UI 显示可恢复错误，Debug 展示 raw parse/fallback trace。
- `skipProviderResponse` 仅用于内部自动观察；v1.0.2 优先收敛为 `runPurpose`，明确区分 `auto_observe`、`user_task`、`internal_diagnostic`。
- `RuntimeDiagnosticModelClient` 仅用于 `internal_diagnostic` deterministic fallback，例如无 provider 时的 debug/form 只读诊断，不服务用户任务主路径。
- AgentLoop 工具调用解析失败时采用 strict JSON repair 策略：首次失败记录 raw output / parse error 并要求模型只输出合法 AgentDecision JSON；repair 一次仍失败，则基于已读取上下文给出保守回答或结构化 fail，不编造未验证内容。

### 上下文策略

- read 工具返回 chunk summary 进入 context，完整 text chunk 进入 ToolResult data / trace 脱敏预览。
- 每个 chunk 必须受 `maxChars` 限制。
- `hasMore` 和 `nextCursor` 进入 context，以驱动下一步工具调用。
- 敏感字段、password、token、API key 继续 mask。
- 页面内容继续视为 untrusted data，prompt injection 文字不能改变系统规则。

## 10. 验收标准

AC1. `bh_page_read_visible_text` 能对长文本分页读取，返回 `hasMore` 和 `nextCursor`。

AC2. `bh_page_read_article` 能优先读取主内容区域，并返回 headings；无正文容器时能 fallback。

AC3. `bh_viewport_get_info` 对 top page 和 frame 都是只读 safe，不改变 scroll position。

AC4. `bh_viewport_scroll` 能滚动 top page，并返回 before/after、boundary、`changedPage: true`、`requiresObserve: true`。

AC5. `bh_viewport_scroll({ target: "iframe", iframeId })` 能滚动可访问 iframe 的 scroll context。

AC6. `bh_iframe_list` 能列出 iframe，并返回稳定 `iframeId`、URL、可访问性和必要的 runtime id。

AC7. `bh_iframe_read` 能读取可访问 iframe 的 summary / visible text / article，并返回 iframe viewport 状态。

AC8. 跨域或不可访问 iframe 返回结构化 limitation/error，不抛未处理异常。

AC9. `bh_iframe_click` 和 `bh_iframe_type` 被删除，iframe 内点击/输入场景迁移到 `bh_element_click` / `bh_element_type_text` 并保留测试覆盖。

AC10. `bh_page_observe` 在 `VISIBLE_TEXT_TRUNCATED` 时提供 next hints，提示继续调用读取工具。

AC11. 用户内容类任务进入真实 AgentLoop/tool-calling 路径；不能只基于 `providerPrompt(snapshot)` 直接回答。

AC12. Agent 在看到 `VISIBLE_TEXT_TRUNCATED`、`hasMore` 或可滚动 iframe 时，会继续调用 read/viewport/iframe 工具，直到达到合理上下文或边界。

AC13. 滚动后 Agent 必须 wait stable 并重新 observe/read，不能用旧上下文回答。

AC14. Trace 记录 read cursor、hasMore、iframeId、底层 frameId、scroll before/after 和 requiresObserve。

AC15. Debug UI 能展示新增工具结果；默认 UI 能展示“继续读取/滚动/读取 iframe”的自然语言状态。

AC16. v1.0 必须工具缺口全部补齐，并同步 `src/tools/README.md` 与 `docs/tools.md`。

AC17. 长页面、lazy-load、iframe 三类 E2E fixture 都有自动化覆盖。

AC18. `npm run build`、`npm run typecheck`、`npm run lint` 和相关单测通过；涉及真实 extension 行为时运行 `npm run test:e2e`。
