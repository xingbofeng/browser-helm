# v0.4 — Complete Cockpit UI Prototype

## 1. 背景

v0.2 到 v0.33 已经具备页面观察、Ref 映射、交互元素、表单字段和安全动作准备数据，但用户还没有一个完整的 side panel 来查看这些信息。浏览器 Agent 如果没有透明 UI，用户不会信任它。

当前用户遇到的问题：Agent 行为像黑箱，无法判断是否安全、是否卡住、是否点错。

现有系统限制：没有完整 extension side panel，也没有页面观察、Ref 映射、交互元素、表单字段、工具结果、Trace、Settings 和基础 Approval 的统一 UI。

为什么现在要做：v1.0 要成为可发布产品，必须先把 v0.2 到 v0.33 的数据包装成可用的浏览器插件驾驶舱。

## 2. 用户故事

US1. 作为用户，我希望在浏览器侧边栏里看到 agent 每一步观察、决策和工具调用，以便判断它是否可靠。

US2. 当 agent 准备执行高风险动作时，作为用户，我希望系统暂停并请求确认，以便避免误操作。

US3. 作为用户，我希望可以随时停止 agent，以便在它行为异常时立即中断。

US4. 作为用户，我希望可以配置 API key、base URL 和 model，以便使用自己的模型提供商。

## 3. 目标

本 Issue 要完成：

- 实现完整 side panel cockpit。
- 实现 4 个核心 tab：页面观察、Ref 映射、交互元素、表单字段。
- 实现 ChatPanel、StepTimeline、ToolInspector、ObservationPanel。
- 实现工具结果展示、Trace / 调试日志、Settings、基础 Approval UI。
- 实现 Run / Stop 状态。
- 实现 UI 与 core 的 RuntimePort 边界，UI 不直接调用 AgentLoop。
- 实现 UI stores：agent-store、trace-store、settings-store、approval-store、page-data-store。
- 展示 full trace / full tool result，但模型上下文仍只消费压缩摘要。
- 实现 ApprovalDialog 原型，展示 action preview、risk、reason、Approve / Deny。
- 实现 run state 可视化：idle、starting、observing、thinking、executing_tool、waiting_for_approval、waiting_for_user、recovering、finished、failed、cancelled。
- Settings 预留用户策略：默认只读、提交前确认、domain 禁用、debug/network 读取开关。

## 5. 产品方案

### 功能入口

用户打开 extension side panel，进入 BrowserHelm Cockpit。

### 用户路径

打开 side panel -> 查看页面观察 / Ref / 交互元素 / 表单字段 -> 输入任务 -> timeline 展示步骤和当前 run state -> 选中 tool result 查看完整 trace 详情 -> 必要时显示基础 approval -> 用户 approve/deny -> runtime resume 或返回拒绝结果。

### 正常状态

正常状态显示四个 tab 的数据、当前 step、最近 observation、最后 tool result。

Approval 状态显示动作、目标元素、风险等级、原因、工具名、参数摘要和用户决策按钮。

Run state 状态显示 agent 正在观察、思考、执行工具、等待审批、等待用户、恢复错误或已经结束。

### 空状态

没有任务时仍可查看当前页面结构化数据；没有页面数据时显示模型配置提醒和示例任务。

### 错误状态

模型未配置、tool failure、content script unavailable、tab data empty、用户 deny approval 都要在 timeline 和 inspector 中明确显示。

### 权限 / 可见性

Settings 只在本地可见；API key 输入需要 masking；approval dialog 必须显示动作、目标、风险和 reason。

## 7. 技术方案

### 现状

已有 agent loop、page observation、ref map、structured page data 和 action readiness，但没有完整 UI。

### 目标设计

React side panel 只依赖 RuntimePort 读取结构化页面数据并控制 agent run。UI 不直接执行工具，也不直接 new AgentLoop、ToolRouter 或 ModelClient。默认按窄侧边栏优先布局，必要时把 inspector 切成抽屉或折叠区。

### 数据流 / 调用链

SidePanel -> RuntimePort.getRunSnapshot / getStructuredPageData -> page-data-store -> tabs render。ChatPanel -> RuntimePort.startRun -> RuntimeEvent updates -> Zustand stores -> timeline/inspector render。UI 展示 full trace / full tool result；Agent turn input 仍由 ContextCompactor 生成摘要。

### 关键类型 / API

```ts
type RunStatus = 'idle' | 'running' | 'waiting_approval' | 'failed' | 'finished' | 'cancelled';

type RunDisplayState =
  | 'idle'
  | 'starting'
  | 'observing'
  | 'thinking'
  | 'executing_tool'
  | 'waiting_for_approval'
  | 'waiting_for_user'
  | 'recovering'
  | 'finished'
  | 'failed'
  | 'cancelled';

type ApprovalRequest = {
  id: string;
  toolName: string;
  argsPreview: string;
  risk: 'safe' | 'low' | 'medium' | 'high';
  reason: string;
  actionPreview?: string;
};

type RuntimePort = {
  startRun(input: StartRunInput): Promise<{ runId: string }>;
  cancelRun(runId: string): Promise<void>;
  sendUserReply(runId: string, message: string): Promise<void>;
  getRunSnapshot(runId: string): Promise<RunSnapshot>;
  subscribeRun(runId: string, listener: (event: RuntimeEvent) => void): () => void;
};
```

### 错误处理

UI 层不吞错误。所有 runtime error 都进入 timeline，并在 selected step 中展示 code/message/retryable。

### 复用与约束

优先复用：RuntimePort、TraceEvent、ToolResult、Approval schema。

不要重复实现：agent state machine、tool router、settings persistence。UI 层不要 import `src/agent/kernel` 或 `src/tools/core/ToolRouter`。

## 10. 验收标准

AC1. 覆盖 US1：side panel 会展示页面观察、Ref 映射、交互元素、表单字段四类 tab。

AC2. 覆盖 US2：当 runtime 产生 approval request 时，UI 以 modal 或 drawer 显示动作、风险、原因，并允许 approve/deny。

AC3. 覆盖 US3：当用户点击 Stop 时，agent run 进入 cancelled 状态，并停止后续工具执行。

AC4. 覆盖 US4：用户可以在 Settings 中保存 API key、base URL、model。

AC5. UI 单测使用 FakeRuntimePort，不调用真实 AgentLoop、真实模型或真实 Chrome API。

AC6. UI 可以展示完整 tool result 和 trace detail，但不会把 UI 展示数据反向注入模型上下文。

AC7. approval_requested / approval_approved / approval_denied events 能进入 timeline 和 ToolInspector。

AC8. RunStateBadge 能展示 observing、thinking、executing_tool、waiting_for_approval、waiting_for_user、recovering 等状态。

AC9. Settings 预留用户策略 UI，但不在 v0.4 强制实现所有策略生效逻辑。

AC10. 已有 v0.1-v0.33 runtime 行为不受影响。

AC11. 实际改动不超出「改动目录结构」；如必须超出，PR 需要写偏离说明。

AC12. 如涉及设计图，实现结果符合「设计图 / 视觉参考」中列出的范围和关键视觉要求，并适配窄 side panel 宽度。
