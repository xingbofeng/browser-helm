# v0.3 — Cockpit UI Prototype

## 1. 背景

v0.2 具备真实页面操作能力，但用户看不到 agent 正在看什么、为什么调用某个工具、哪一步失败，也无法停止或审批。浏览器 Agent 如果没有透明 UI，用户不会信任它。

当前用户遇到的问题：Agent 行为像黑箱，无法判断是否安全、是否卡住、是否点错。

现有系统限制：没有 side panel、timeline、tool inspector、observation preview、settings、approval dialog。

为什么现在要做：v1.0 要成为可发布产品，必须先建立 cockpit UI。

## 2. 用户故事

US1. 作为用户，我希望看到 agent 每一步观察、决策和工具调用，以便判断它是否可靠。

US2. 当 agent 准备执行高风险动作时，作为用户，我希望系统暂停并请求确认，以便避免误操作。

US3. 作为用户，我希望可以随时停止 agent，以便在它行为异常时立即中断。

US4. 作为用户，我希望可以配置 API key、base URL 和 model，以便使用自己的模型提供商。

## 5. 产品方案

### 功能入口

用户打开 extension side panel，进入 BrowserHelm Cockpit。

### 用户路径

输入任务 -> 点击 Run -> timeline 实时展示步骤 -> 选中 step 查看 tool args/result -> 遇到 approval 弹窗 -> 用户 approve/deny -> 任务继续或停止。

### 正常状态

Running 状态显示当前 step、最近 observation、最后 tool result。

### 空状态

没有任务时显示 welcome、模型配置提醒和示例任务。

### 错误状态

模型未配置、tool failure、content script unavailable、用户 deny approval 都要在 timeline 和 inspector 中明确显示。

### 权限 / 可见性

Settings 只在本地可见；API key 输入需要 masking；approval dialog 必须显示动作、目标、风险和 reason。

## 7. 技术方案

### 现状

已有 agent loop 和 page tools，但没有 UI。

### 目标设计

React side panel 通过 background RPC 控制 agent run。UI 不直接执行工具。

### 数据流 / 调用链

ChatPanel -> background.startRun -> trace updates -> Zustand stores -> timeline/inspector render。

### 关键类型 / API

```ts
type RunStatus = 'idle' | 'running' | 'waiting_approval' | 'failed' | 'finished' | 'cancelled';

type ApprovalRequest = {
  id: string;
  toolName: string;
  argsPreview: string;
  risk: 'sensitive';
  reason: string;
};
```

### 错误处理

UI 层不吞错误。所有 runtime error 都进入 timeline，并在 selected step 中展示 code/message/retryable。

### 复用与约束

优先复用：TraceEvent、ToolResult、Approval schema。

不要重复实现：agent state machine、tool router、settings persistence。

## 10. 验收标准

AC1. 覆盖 US1：当用户运行任务时，side panel 会展示实时 step timeline、tool call 和 tool result。

AC2. 覆盖 US2：当 runtime 产生 approval request 时，UI 显示动作、风险、原因，并允许 approve/deny。

AC3. 覆盖 US3：当用户点击 Stop 时，agent run 进入 cancelled 状态，并停止后续工具执行。

AC4. 覆盖 US4：用户可以在 Settings 中保存 API key、base URL、model。

AC5. 已有 v0.1/v0.2 runtime 行为不受影响。

AC6. 实际改动不超出「改动目录结构」；如必须超出，PR 需要写偏离说明。
