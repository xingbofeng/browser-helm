# BrowserHelm v1.1-v1.6 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把外部审计指出的 v1.1-v1.6 未完成能力、安全阻断和架构债统一转成可执行、可验收的任务池。

**Architecture:** 先补齐不可绕过的 runtime 安全边界，再逐版本补完能力。每个版本能力必须同时包含产品入口、runtime/tool 实现、policy/approval 边界、UI 展示、自动化测试和文档验收，不能只以 tool constant、浅层 wrapper 或 prompt guidance 计为完成。

**Tech Stack:** WXT MV3 extension, React, TypeScript, Zod, Vitest, Playwright extension E2E, Chrome debugger/CDP, IndexedDB/Dexie, chrome.storage.

---

## Completion Rules

- v1.1-v1.6 的未完成能力需要继续完成；不能因为存在 P0 安全问题就从 scope 中删除。
- 发布顺序必须是：安全阻断先解除，然后功能补完逐项验收；功能实现不得绕过未完成的安全边界。
- 每个任务必须给出真实验证结果，区分 static check、unit/dom test、extension E2E、real model E2E、manual/native side panel verification。
- 所有新增或变更工具必须同步 `src/tools/README.md`、TSDoc 工具头部说明、tool manifest/registry 测试和 release check。
- 任何 mutating tool、debugger/CDP、clipboard、download/file、storage、workflow replay、iframe/pointer action 都必须经过 execution-layer authorization；ToolSelector 只负责模型可见性，不算安全 enforcement。
